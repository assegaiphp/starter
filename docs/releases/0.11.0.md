# AssegaiPHP Starter 0.11.0

New projects created with the official starter now select the published
AssegaiPHP Core `^0.11.0` compatibility line. Each application continues to own
its resolved Composer lock file; the starter does not distribute dependencies
or a lock file.

## What changed

- Selects Core 0.11.x, including its optional bootstrap runtime-path contract.
- Retains the native PHP bootstrap, configuration layout, setup scripts and
  public-asset routing.
- Includes application-key setup and rotation guidance in the README.
- Removes CI's deferred-check mode. Dependency installation, security auditing,
  tests and HTTP smoke checks now run unconditionally on PHP 8.4 and 8.5;
  unavailable required packages fail the build.

## Create a project

```bash
composer create-project assegaiphp/starter:^0.11.0 my-app
cd my-app
composer run start
```

Installation creates private `.env` and `config/secure.php` files from their
tracked examples without overwriting existing files. Generate a private
application key before using features that depend on it; see the README for
`assegai key:generate` and key-rotation guidance.

## Existing applications

Updating the starter does not modify projects that have already been created.
Existing applications choosing Core 0.11 should review their Composer
constraint, resolve and test their application-owned lock file, and read
[Core's release and upgrade notes](https://github.com/assegaiphp/core/releases/tag/0.11.0).
The external runtime-path contract remains opt-in. PHP 8.4 or later is required.
