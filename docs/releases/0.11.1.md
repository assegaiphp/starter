# AssegaiPHP Starter 0.11.1

This correction requires Core `~0.11.1`, excluding Core 0.11.0 and later minor
lines. It selects the corrected Core baseline for the coordinated framework
0.11 release. The native bootstrap, configuration layout, application-key setup
and public-asset routing are unchanged.

## Create or upgrade an application

After the coordinated packages have been published:

```bash
composer create-project assegaiphp/starter:~0.11.1 my-app
cd my-app
composer run start
```

The starter continues to distribute neither dependencies nor a lock file.
Composer creates the application's own lock and copies the example environment
and secure configuration without overwriting existing local files. Generate
and protect the application key as described in the README.

Updating Starter does not change applications already created from it. Review
the application's existing constraints and customizations before selecting the
coordinated Core baseline. Resolve and test its own lock file after the required
packages are available. Preserve stricter custom requirements; resolve a
conflict explicitly rather than lowering them. Existing framework 0.11
applications must use Core 0.11.1 or a compatible later 0.11 patch to adopt this
correction.

## Coordinated release checks

All framework modules participate in the 0.11 inventory. Historical dependency
streams remain explicit: Attributes stays on the compatible 1.0 line, and
RabbitMQ and Beanstalkd use their coordinated 1.2 line with Common 0.11.
Starter does not directly require those packages; the shared validator checks
the planned graph and resolved dependencies across the complete inventory.

Console owns the shared reader and validator. Starter's maintenance script
forwards to it without adding a second validator or a runtime dependency on
Console. With a Console build providing `release:check`, pass the reviewed
files explicitly:

```bash
composer run release:check -- \
  --inventory=/path/to/reviewed-release.json \
  --modules=/path/to/framework-modules.json \
  --evidence=/path/to/generated-owner-evidence.json \
  --stage=prepare
```

Preparation requires evidence bound to the exact candidate source, dependency
resolution and release-note checks. The complete release also requires CLI
recommendations and Website's versioned guide, upgrade path, article and
updates-advisor checks. Missing or stale evidence blocks readiness. The
inventory and membership files must be reviewed together and identified by
their exact digests; do not substitute a moving branch.

The separate `--stage=publish` check additionally verifies actual stable
package publication and source identities. Preparation does not establish
publication or authorize publishing. Website updates its lock after the
required packages are published, verifies the resulting application and
deploys last. Andrew creates the release branches, tags and releases.

The existing PHP 8.4/8.5 CI remains unconditional: manifest validation, lint,
dependency resolution, audit, tests and HTTP smoke checks must pass. A missing
Core 0.11.1 package fails dependency resolution; there is no deferred-check mode.
