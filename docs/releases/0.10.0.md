# AssegaiPHP Starter 0.10.0

The 0.10.0 starter is the Composer `create-project` counterpart to the project generated by Assegai Console 0.10.

## Highlights

- selects the AssegaiPHP Core `^0.10.0` compatibility line
- requires PHP 8.4 or later
- provides the current module, controller, service, component, and public-asset project shape
- adds `config/auth.php` for authentication redirect policy and framework-owned session settings
- keeps shared application configuration in `config/default.php`
- creates local `.env` and `config/secure.php` files without overwriting existing files
- uses Pest for the starter smoke tests
- supports both `composer run start` and the Assegai CLI workflow
- omits `composer.lock` so each created application owns its resolved dependency set

## Create a project

```bash
composer create-project assegaiphp/starter my-app
cd my-app
assegai serve
```

The updated starter package must be published only after the coordinated first-party 0.10 packages are available to Composer. This ensures a newly created project can resolve Core and its aligned dependencies immediately.

## Authentication configuration

The scaffold includes `config/auth.php` with an application-controlled login URL and session cookie policy. The built-in `LoginRedirectFilter` remains opt-in; the presence of this configuration file does not enable redirects globally.

Applications should replace `/auth/login` when their public login route uses a different path. Applications with bespoke behavior can configure a filter instance or supply their own exception filter.

## Validation

Before publishing the starter package:

1. validate `composer.json` strictly
2. create a project from the prepared package in an empty directory
3. confirm Composer creates `.env`, `config/secure.php`, and an application-owned lock file
4. run the generated project's tests
5. start it with `assegai serve` and smoke-test the home page and public assets
